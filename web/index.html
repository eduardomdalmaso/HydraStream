// PIPELINE BOTTLENECK DIAGNOSTICS & TELEMETRY GUIDE

1. Deteção de Gargalo na Decodificação (Hardware Decode Latency Δt)

● < 1.5 ms (Ideal): Decodificação por GPU NVIDIA NVDEC sem sobrecarga.
● 1.5 ms – 3.0 ms (Alerta): O processo de decodificação no servidor está próximo do limite.
● > 3.0 ms (Gargalo Crítico): Indica perda de frames e estouro de CPU/GPU. Recomenda-se migrar de motor de decodificação em STREAM MATRIX.

2. Deteção de Gargalo na Transmissão de Rede (Inbound Flow Kbps)

● Flutuação > 30% na Banda: Sinaliza oscilação na rede RTSP ou câmera instável.
● Inbound Flow = 0 Kbps: Câmera offline ou desconectada pelo MediaMTX.
● O HydraStream monitora o fluxo de forma passiva, sem alterar o bitrate enviado pela câmera de origem.

3. Transporte de Memória Zerada (POSIX SHM vs CUDA IPC)

● POSIX SHM: Memória compartilhada no Linux (`/dev/shm`) em anel atômico sem lock para consumo por scripts Python/C++ em CPU.
● CUDA IPC: Passagem de ponteiros de tensores diretamente na VRAM da GPU para o NVIDIA Triton Inference Server sem cópia na RAM.

4. Módulo de Avisos & Falhas do Cluster

Alertas críticos (Nó parado, memória SHM saturada, reconexão de stream) são exibidos no topo do Dashboard Control Panel com botão de confirmação `[ ACKNOWLEDGE / CLEAR ]`.
